## What this project covers

Build a reproducible crop-data ingestion and reporting pipeline with explicit mapping, observation keys and transaction behaviour.

## Why this matches Imran’s experience

Support fit: **Strong match**. This assessment is based on Python automation, data validation and database-backed applications. See the [related portfolio evidence](/network-automation-python/). This is a proposed support topic, not a claim that this exact project has already been delivered.

## Main modules to plan

- Read source CSV fields as text and validate configured mappings.
- Implement observation keys, numeric parsing and database transactions.
- Expose analytical reports through a local Streamlit interface.

## Technology and feasibility checks

PostgreSQL ETL and Streamlit extend the existing Python foundation. Follow the supplied input contract; do not replace it with an external AI service or assume large-scale performance from a small sample.

## Testing and demonstration evidence

Test malformed numeric values, duplicate observations, reruns and rollback on invalid records. Reconcile report totals with the accepted source rows.
